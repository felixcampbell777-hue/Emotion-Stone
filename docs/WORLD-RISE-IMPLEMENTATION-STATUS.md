Offline rest/death rules remain unchanged. Hosting targets a trusted LAN/private VPN; it is not an unqualified claim of public-Internet hardened hosting.

## Reproducible checks and ownership

Use `tools/platform.sh` on macOS/Linux and the existing `tools/platform.cmd` on Windows. Both use the portable Python command dispatcher and disposable userdata. Focused script fixtures can run as `tools/platform.sh check-script scripts/network/wr_actor_parity_checks.gd` (and the other named `*_checks.gd` fixtures); normal content validation remains `tools/platform.sh validate`. Native views use the existing capture flow, including `appearance` and `world-rise-menus`. Linux server export/hosting commands are documented in `docs/DEDICATED-SERVER.md`, `hosting/README.md` and `tools/server_export.py`; refresh exports after source changes before quoting package results.

Shared integration source has one owner: main/Actor/project settings, equipment/stat/save glue and the client presentation/prediction hooks. Weapon, motion, appearance, audio/voice, network authority, world controllers, UI and portable tooling remain separate feature-owned modules. See the integration contract for exact APIs. No test uses the human's original save, and no portable identity/private credential or machine tool path belongs in Git.
