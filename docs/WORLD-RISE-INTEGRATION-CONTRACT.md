# World Rise runtime integration contract

Implementation coordination, October 18, 2026. These APIs preserve the offline save and simulation contract.

- `main.gd`, `actor.gd`, `project.godot`, `magic_items.gd`, `world_rise_stats.gd`, and `save_store.gd` have one integration owner. Feature owners supply separate modules and coordinate hooks.
- `game.online_session_active()` asks the attached session. `game.simulation_active()` gates gameplay clocks, enemies, projectiles, hazards and damage. `actor.input_enabled` gates local controls; `actor.simulation_enabled`/`online_mode` allow committed actions and vulnerability through online menus. Offline menus retain the existing pause behavior.
- Actor owns action state/time, stamina, interruption, and weapon runtime. `actor.action_context()` returns actor ID, stable per-actor action ID, action, phase and weapon type. `presentation_event(Dictionary)` carries these plus an event ID/index; presentation never advances action clocks.
- `WeaponProfiles.kind(item_id)`, `profile(item_id)`, `apply_tuning(actor,item_id)` adapt the equipped item without replacing legacy greatsword tuning. `WeaponRuntime.configure(game,actor)`, `equip`, `enabled`, `active`, `begin_primary`, `release_primary`, `cancel`, `tick`, `pose`, `hand_targets`, `contact_segments`, `action_context`, and `movement_multiplier` own additional weapon behavior. `update_preview()` is presentation-only and is called for the visible online bow after its accepted pose; it never spends ammunition or advances clocks.
- `game.resolve_weapon_contact(context,target,amount,direction,strong)` is the offline damage dispatcher. Online authoritative session requests replace local contact/reward side effects. Only greatsword steel confirms greatsword kill progress.
- Appearance is a validated portable value object: `AppearanceProfile.default_profile/valid/normalized/snapshot`, `CharacterAppearance.apply(actor,profile)`, and `game.commit_appearance(draft)`. Legacy saves default to the original appearance. Online Apply sets `appearance_commit_pending` before dispatch and resolves `appearance_commit_finished(accepted,message)` from the authoritative result; rejected changes retain the draft. `CharacterAppearance.clear(actor)` restores shared original art before entering older modes.
- `game.wr_session` and `game.network_session` refer to the same session Node. Networking owns authority, identity, world persistence and transport; integration owns visible-client command/snapshot flows.
- `network/wr_actor_bridge.gd` uses the actual Actor and native world controllers; setup/rebind sets grounded motion. `wr_actor_pose` serializes accepted action, rig, transition, gait and view state. `wr_prediction` replays bounded unacknowledged commands on a silent shadow bridge. Session receive queues snapshots; `record_input()` flushes and replays only inside the main physics callback. Visible online Actors have autonomous physics disabled. Input acknowledgement means consumed simulation input, with a separate accepted action acknowledgement.
- Native enemy/effect snapshots use `worldrise.apply_authoritative_enemies()` and `apply_authoritative_effects()`; client effect nodes have gameplay processing disabled. Remote capsules preserve the shared solid-player policy.
- Audio receives actor presentation events and resolved contacts. Appearance, connection and settings screens expose `configure(game)`, `open()`, `close()` and `visible` for common overlay handling.

Feature modules must use the same configured weapon/action geometry for visible presentation and real collision. No roll immunity, tree-version changes, private-save edits, or implicit new equipment acquisition rules are part of these interfaces.

First-person contact frames are sampled from the accepted Actor's animated source/personal head and root, including view attenuation and the physical camera sphere cast. `network/wr_view_frame.gd` shares this frame between the visible client and camera-free authority. Actor physics advances the view and personal gait envelopes once per tick; rendering reads those envelopes without advancing them. Greatsword contacts use the Actor's transformed blade base/tip and swept capsule tests. The retained greatsword collision envelope uses a 0.05m half-width for personal beta steel and 0.12m for original steel, matching the established playable Actor; those collision margins are intentionally unscaled. Rendered sword width still follows the equipment transform scale. Contact parity therefore means the same accepted base/tip, transverse basis, sweep and collision envelope on client and authority; it does not claim full rendered mesh edge coverage or add a new greatsword contact-reach adjustment.

Voice remains opt-in and muted initially. `game.voice` uses the authenticated session roster and transport, with proximity/group PTT suppressed while text fields own focus. The macOS optional native capture path preserves engine output when microphone permission is denied; Windows uses engine capture. Product quit awaits `voice.shutdown_and_drain()` and then `audio.shutdown_and_drain()` after durable session departure.

Combat-only player anatomy uses `player_hurt.gd` queries over the accepted animated native rig. `game.combat_player_targets(source_actor)` filters logical identity, world, alive state and lifecycle; `combat_player_exclusions(source_actor)` excludes both shadow and visible-self movement RIDs. The shared ballistic sweep chooses the nearest hurt contact versus actual scenery; launch obstruction, preview and live arrows use the same APIs. Movement/terrain capsules, roll vulnerability, authored steel paths and cosmetic-independent stats remain unchanged.

Network persistence uses the bounded versioned lossless envelope for server and portable-client files, with exact Variant payload/checksum and strict data-only validators. Ordinary offline save JSON is separate. Development-network files without the envelope are rejected/preserved rather than silently replaced from backups.
