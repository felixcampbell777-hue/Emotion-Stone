# World Rise voice

Confirmed channels: hold **V** for proximity, **B** for the Friends group. Proximity is same-floor within35m with distance attenuation; Friends spans floors. Microphone defaults off. Windows uses Godot capture; macOS uses the optional maintained input-only native extension to preserve Godot output when permission/device is unavailable. Capture runs only while PTT is held or the user explicitly tests its local level. Focus loss, editable-text focus, overlay input cancellation, mute/deafen, device change and disconnect stop capture. No microphone audio is written to disk.

## Integration

`WorldRiseVoice` owns microphone/settings, native Opus processing, bounded60ms-start/eight-packet jitter buffering, per-peer mutes, distance attenuation and built-in generator playback on bus `Voice`. Configure after the audio bus layout, then connect `outgoing_frame` to `WRSession.send_voice`, session `voice_received` to `receive_frame`, and `voice_activity` to audio ducking. Authenticated snapshots provide the separate full voice roster independent of visual floor interest. Simulation and character saves remain outside voice. Playback reset retires the old emitter node and lazily starts a fresh emitter, preserving generator configuration, codec, jitter and mute rules. `await shutdown_and_drain()` stops reception/capture and weakly observes retired playback references until zero, with a1.5s failure deadline; product quit awaits it before audio shutdown. The rapid-reset fixture verified128 repeated decode/mute/deafen cycles plus initial disconnect (159 active checks), with zero retained playback instances and empty stderr. Four static class-name metadata entries remain separately documented below.

`WorldRiseVoiceUDP` is the voice-only network path. Gameplay remains ENet. The server starts voice on a separate configured UDP port (normally game+1), enrolls at most8 authenticated peers with fresh32-byte random keys and their actual ENet remote IP, then delivers each key/voice port in the authenticated game acceptance. Client resolution uses that actual ENet IP, preserving address family/VPN route. Server-authoritative positions/floor/group still feed `WorldRiseVoiceRelay`.

The payload has a fixed28-byte binary header, <=400-byte20ms Opus payload and32-byte HMAC-SHA256 tag; datagrams cannot exceed512bytes. Header fields are magic/version, kind, channel, sender, transport sequence, voice-frame sequence and payload size. Distinct client→server/server→client HMAC domains prevent reflection; outbound authentication uses each recipient's unique key. Keys authenticate voice; **LAN/VPN supplies confidentiality**. This protocol does not claim encryption on an untrusted Internet connection.

A quiet client sends an authenticated HELLO heartbeat eachsecond; the server learns its NAT endpoint only after membership/IP/HMAC/replay validation and returns an equally sized authenticated ACK. Registration retries are bounded; five seconds without ACK causes re-registration. Unknown/invalid packets receive no response. IPv4-mapped/IPv6 forms are normalized.64-packet transport and frame replay windows allow genuine reordering while rejecting duplicates. Voice routing applies source60frame/s and16KBpayload/s limits, same-floor proximity or matching server group. Each node consumes at most64datagrams per frame. Per-source packet and byte budgets, a client512packet/s budget and server512KiB/s aggregate egress cap bound work/bandwidth; excess frames drop without an unbounded queue.

Godot ENet's automatic unreliable throttling dropped much of the early voice experiment before RPC receipt even on localhost. The dedicated authenticated UDP route avoids that layer while retaining independent identity/rate/interest validation. Legacy ENet voice RPC input is disabled.

## Verification

Focused commands use disposable user data. Every voice probe uses always-active checks rather than native `assert()`, since exported release templates remove assertions and their expressions. Failed checks return immediately and exit1; UDP registration/receive loops have active deadlines. `-- --voice-fixture-force-failure` deliberately fails the first check to verify release guarding (expect exit1 and no PASS).

- `./tools/platform.sh check-script scripts/voice/voice_checks.gd`: real native Opus encode/decode with nonzero960-frame PCM and relay bounds.
- `./tools/platform.sh check-script scripts/voice/voice_playback_checks.gd`: built-in generator, bounded reorder, duplicates/mute/focus/disconnect.
- `./tools/platform.sh check-script scripts/voice/voice_text_focus_checks.gd`: actual LineEdit/TextEdit focus blocks V/B capture and cancels held speech until a fresh press.
- `./tools/platform.sh check-script scripts/voice/voice_udp_checks.gd`: actual UDP sockets, HMAC domains, corruption/replay/unauthenticated reflection rejection and reordered relay.
- `./tools/platform.sh check-script scripts/voice/voice_native_checks.gd`: macOS optional native loading and nonprompting denied permission behavior. For physical CoreAudio output verification the same fixture was run with `--headless --audio-driver CoreAudio` using isolated tooling environment.
- `python3 game/scripts/voice/run_transport_checks.py --peers 2` or `8`: real authenticated game sessions with synthetic tones through the normal dedicated UDP path and all remote PCM playback pipelines. Local acceptance requires >=95% expected frames, all streams, bounded jitter and clean exits/errors. `--crossfloor` checks group delivery while proximity is filtered. `--conditioned` puts each client’s gameplay AND voice through separate controlled proxies at150ms RTT, ±20ms per-leg jitter and2% per-leg loss; acceptance retains >=95% of expected frames with every stream decoded and the same bounded jitter/clean-exit requirements. The synthetic source allows at mostfour catch-up frames per process tick to maintain200 frames overfour seconds despite main-thread scheduling. Only the latest compact outcome per named scenario is retained (`voice-transport-local-crossfloor-2.json`, `voice-transport-conditioned-8.json`); `output/verification/voice-transport.json` also points to the latest run outcome. Repeating a scenario replaces its prior result.
