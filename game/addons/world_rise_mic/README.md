# Optional World Rise macOS capture

The maintained source and build recipe live in `game/scripts/voice/native/`. This small GDExtension uses Apple's system AVFoundation/AVAudioEngine and CoreAudio frameworks for **input only**; Godot 4.5.1 retains its working CoreAudio output with engine microphone input disabled on macOS. Windows continues through Godot's built-in capture path.

The runtime is a universal arm64+x86_64 binary with pinned Godot 4.5 bindings. `PROVENANCE.json` records hashes, binding revision, build version and deployment target. Custom code is MIT (`LICENSE`); Godot bindings are MIT (`GODOT-CPP-LICENSE`). Apple frameworks are linked from the operating system, not bundled. No third-party audio capture library is redistributed.

Run `python3 game/scripts/voice/native/build_macos.py` on macOS with Apple command-line developer tools installed. It uses pinned godot-cpp commit `e83fd0904c13356ed1d4c3d09f8bb9132bdc6b77` and SCons4.10.1 in an ignored user build cache, builds both architectures, creates and ad-hoc signs a universal runtime, updates its integrity pin and provenance. It does not alter Godot or system privacy preferences. Close running clients before rebuilding. Distribution signing/notarization is separate release work.

`native_capture.gd` verifies the shipped payload hash, extracts that exact library to an immutable hash-named `user://voice-native/` cache and creates a descriptor there. Only macOS loads it; Windows/Linux do not scan a macOS-only extension. Export must include `addons/world_rise_mic/libs/*.bin` in the Mac client PCK. Cache contents contain native runtime code only, never microphone audio.

Capture starts only while push to talk is held or the user explicitly tests the local microphone level. No idle or unfocused capture runs. Native authorization is checked first. Existing denial/restriction fails cleanly; a system permission prompt is requested only for an explicit opt-in when permission is undetermined. Permission is never granted by code. The callback downmixes and bounds floats into a fixed 9600-sample ring, uses a non-blocking mutex attempt, drops on contention/overflow, and never calls Godot or writes to disk from the audio thread. The main thread reads PCM into the existing Opus encoder. Stop/device change/focus/PTT cancellation clear buffers.

Actual verification on macOS arm64 with Godot4.5.1: native loading, permission query (`denied`), nonprompting capture failure, stop/reinitialization/device-failure calls all passed; **CoreAudio output remained CoreAudio** throughout. This fixes the engine's previous fallback-to-Dummy behavior when its own input device initialization failed. No real microphone signal or listening-quality pass is claimed until the human enables microphone permission for the exported application and participates in a conversation. x86_64 slice is built and inspected, not executed on this arm64 machine.
