## Runtime boundaries

`WorldRiseVoiceCodec` calls the native encoder/decoder only on the main thread. The native AudioEffect is **never attached to a bus**, and the native AudioStream is **never played**. Godot's `AudioEffectCapture` (Windows), the optional `world_rise_mic` AVAudioEngine capture (macOS), and `AudioStreamGenerator` own audio callbacks. This avoids relying on older TwoVoIP shared ring-buffer thread behavior. Fixed 48 kHz/960-frame/20ms Opus payloads, 24kbps, duplicated stereo capture; source mixer input is resampled natively when needed. No microphone samples or conversation recordings are written to disk.

The server receives opaque Opus frames only from authenticated peers, checks packet size/duration, monotonic sequence and aggregate rate, then applies same-floor 35m proximity or server-assigned group membership. These are initial voice presentation defaults; they do not alter combat/aggro distances. The client bounds per-peer reorder buffering to eight packets, waits 60ms at stream start, rejects duplicates, and drops missing/stale frames. This is basic jitter handling, without retransmission, adaptive jitter, echo cancellation or packet-loss concealment. Use headphones for acceptance listening. The older decoder does not expose libopus decode errors; malformed packets are bounded and libopus-rejected frames may yield stale PCM. Future upgrade/rebuild should expose decoder results before wider public-server deployment.

Microphone capture is opt-in, initially off; only PTT emits data. Device change, mute/deafen, UI/focus loss and disconnect cancel PTT; input absence produces a device/permission status. Bus Voice owns incoming speech volume. Voice device preference is local and session peer mutes do not affect character saves.

## Focused checks (disposable userdata)

- `./tools/platform.sh check-script scripts/voice/voice_checks.gd`: real native Opus encode/decode with nonzero PCM, authenticated relay routing/rate/replay guards. **Passed Godot4.5.1 macOS arm64.**
- `./tools/platform.sh check-script scripts/voice/voice_playback_checks.gd`: built-in generator receives decoded audio; reordered frames/duplicate/mute/focus/disconnect. **Passed with Dummy driver. No audible quality claim.**
- `voice_device_checks.gd` can run with CoreAudio using the tooling's isolated process wrapper. Dummy driver produced capture packets and exercised stop/cancel; **Historical initial CoreAudio attempt hit a cached-engine AMFI signature failure (tooling repaired the byte-identical engine inode). CoreAudio device enumeration then succeeded: default MacBook Air Microphone, iPhone Microphone, built-in speakers, all 48kHz. With enable_input=false the uninitialized input unit returned -50; enable_input=true fixed that prerequisite but failed assigning the default input device at CoreAudio source line408 and fell back to Dummy.** The maintained optional macOS capture wrapper now handles denial without affecting Godot CoreAudio output; its actual denied-permission/CoreAudio test passed. No system microphone permission was changed. Actual microphone quality/permission acceptance remains unverified. Engine input stays disabled on macOS to avoid its fallback; Windows enables the built-in input driver. Do not interpret the Dummy result as a microphone pass.

Required release acceptance: real two-client macOS/Windows conversations for both channels, headphones/speakers and denied/revoked permission/device unplug, export signing/notarization and usage-description permission prompts; Linux Docker relay with 2–8 clients and packet loss/jitter. These checks have not been claimed complete.

It runs authenticated game sessions and the dedicated HMAC voice UDP path, including all remote PCM pipelines with disposable data; only the latest compact `output/verification/voice-transport.json` is retained.
